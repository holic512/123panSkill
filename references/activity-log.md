# Private activity log

Use `scripts/record_activity.py` to retain a structured outcome record for a
scoped 123pan client operation, upstream review, archive refresh, or skill
maintenance task. This is a local audit aid; it does not grant permission,
replace user confirmation, send telemetry, or validate a network operation.

## Location and retention

By default, the recorder appends to `.123pan-skill/activity.jsonl` relative to
the directory from which it is run. The directory is created with owner-only
permissions when possible, and newly created log files use mode `0600`. The
path is Git-ignored by this skill repository.

Use `--log-file /user-controlled/path/activity.jsonl` only when a different
local retention location is required. Do not use a tracked repository file,
shared drive, paste service, issue, commit message, or external logging system
without separate authorization and a review of its data-handling rules.

Records append rather than replace earlier entries. Retain them only for the
period needed for local troubleshooting or audit, then remove the local log
using the normal file-retention process for the active workspace. Do not add
runtime logs to the upstream archive.

## Schema

Each JSONL line is one schema-version-1 object:

| Field | Purpose | Data restriction |
| --- | --- | --- |
| `event` | Fixed event name | Always `123pan-skill-activity` |
| `schema_version` | Format version | Always integer `1` |
| `timestamp` | UTC event timestamp | Generated by recorder |
| `run_id` | Correlation identifier | Generated UUID or supplied UUID |
| `action` | Operation category | Controlled enum only |
| `outcome` | Final operation state | Controlled enum only |
| `side_effect` | Observed read/write scope | Controlled enum only |
| `authorization` | Confirmation state | Controlled enum only |
| `source_snapshot` | Source context label | Controlled identifier only |
| `reason_code` | Coarse result category | Controlled identifier only |
| `validations` | Completed checks | Controlled identifier list only |

There is intentionally no message, target, prompt, URL, path, file-name,
credential, token, cookie, share-link, or response-body field. Do not modify a
record by hand to add one.

## Recording an outcome

Run the script after the final result is known. Choose values that describe what
actually happened:

```bash
python3 scripts/record_activity.py record \
  --action client-inspection \
  --outcome succeeded \
  --side-effect none \
  --authorization not-applicable \
  --source-snapshot archive-baseline \
  --reason-code source-inspected \
  --validation python-syntax-check
```

Use `remote-read` or `remote-write` only when that access actually occurred.
For a blocked request, use `outcome=skipped` or `outcome=failed` and a coarse
reason code such as `login-unavailable`, `network-unavailable`, or
`user-cancelled`. Do not include the failed URL or any account details.

Commands:

```bash
python3 scripts/record_activity.py location
python3 scripts/record_activity.py list
python3 scripts/record_activity.py validate
```

`list` and `validate` reject records that do not conform to the schema. Supply
`--log-file` before the subcommand to inspect another explicit local file.

## Controlled values

Allowed values for the main fields are deliberately small:

| Field | Values |
| --- | --- |
| `action` | `client-inspection`, `remote-read`, `remote-mutation`, `upstream-review`, `archive-refresh`, `skill-maintenance` |
| `outcome` | `started`, `succeeded`, `failed`, `skipped` |
| `side_effect` | `none`, `local-write`, `remote-read`, `remote-write`, `mixed` |
| `authorization` | `not-applicable`, `confirmed`, `not-confirmed` |
| `source_snapshot` | `archive-baseline`, `working-copy`, `external-runtime`, or `upstream-history-<safe-id>` |

`reason_code` and each `validation` must be lowercase, hyphen-separated labels
of at most 80 characters. Prefer coarse labels such as `archive-integrity-ok`,
`source-inspected`, `remote-update-complete`, or `network-unavailable`.
